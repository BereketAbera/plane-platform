# Terraform

Terraform owns the cluster's foundation and hands everything else to Argo CD
([contract section 4](../../docs/platform-contract.md)).

**The kind CLI creates the cluster, not Terraform.** `scripts/cluster-up.sh` does that first. The Kubernetes and Helm
providers read the kubeconfig during plan, and the [provider docs](https://registry.terraform.io/providers/hashicorp/kubernetes/latest/docs)
warn against creating a cluster and its Kubernetes resources in one module.

| Path | Status | Contents |
|---|---|---|
| `modules/foundation` | Used | Namespaces with PSA and platform labels; ResourceQuota and LimitRange per Plane namespace; CoreDNS rewrite |
| `modules/argocd` | Used | Argo CD release; second release with the AppProjects and the root Application |
| `environments/local` | Used | Root module for the kind cluster. State at `.local/terraform/local/terraform.tfstate` |
| `environments/dev`, `environments/prod` | **Untested templates** | Interface documents for pass 2. Nothing to run |

## Workflow

The cluster must be running. From the repo root, with `.tools/bin` on `PATH`:

```bash
TF=infrastructure/terraform/environments/local

mkdir -p .local/terraform/local
terraform fmt -check -recursive infrastructure/terraform
terraform -chdir=$TF init
terraform -chdir=$TF validate
terraform -chdir=$TF plan -out=../../../../.local/terraform/local/plan.tfplan
terraform -chdir=$TF apply ../../../../.local/terraform/local/plan.tfplan
```

`terraform init -backend=false` is enough for `validate`, and needs no cluster. Providers are pinned, and
`.terraform.lock.hcl` carries hashes for `darwin_arm64` and `linux_amd64`. After a provider bump, regenerate both:

```bash
terraform -chdir=$TF providers lock -platform=darwin_arm64 -platform=linux_amd64
```

Admin password, generated by Argo CD at first start and never in Git or state:

```bash
kubectl --context kind-plane-platform -n argocd get secret argocd-initial-admin-secret \
  -o jsonpath='{.data.password}' | base64 -d
```

The CLI reaches the server through Traefik with `argocd login argocd.localhost --grpc-web --plaintext`.

## Destroy

```bash
terraform -chdir=$TF destroy
```

Read what this does before running it. For normal teardown use `make destroy`, which deletes the cluster and
this state together.

- **It deletes the namespaces, and with them every PVC and all Plane data.** Run `make backup ENV=all` first.
- **It breaks CoreDNS.** The provider's delete of `kubernetes_config_map_v1_data` removes the `Corefile` key, and
  CoreDNS cannot mount its config at the next restart. Delete the cluster afterwards rather than reusing it.
- It leaves Argo CD's CRDs (`crds.keep`). The root Application has no finalizer, so removing it does not cascade
  through its children.

## Decisions

**AppProjects and the root Application use a second `helm_release`.** `kubernetes_manifest` needs the CRD at plan
time, which fails on an empty cluster. The chart's `extraObjects` fails too, later: the chart ships its CRDs as
ordinary templates, not in `crds/`, and Helm maps every object in a release to an API before it creates any. A
second release installs after the first, so the CRDs exist. It costs one small chart, in `gitops/bootstrap/chart`.

**That chart's content hash is passed as a value.** The Helm provider only sees a local chart's template edits
when `Chart.yaml`'s version changes. The hash makes every edit show up in the plan.

**The Argo CD IngressRoute is not in Helm values or the bootstrap chart.** Traefik's CRD does not exist until Argo CD
has synced Traefik, so Helm would fail with the same "no matches for kind" error. The root Application syncs it from
`gitops/bootstrap/argocd-route` at wave -8, gated by the `traefik` child's health. Until then Argo CD has no route, so
use `kubectl -n argocd port-forward svc/argocd-server 8080:80`.

**Terraform owns the Argo CD release, and Argo CD does not manage itself.** A bad sync cannot take down the controller
that would apply the fix, and `terraform apply` works while Git is down. Argo CD upgrades are therefore not GitOps.

**ResourceQuota sizing** is computed in `modules/foundation/main.tf` from the contract's budget: 2704Mi requests and
7904Mi limits per Plane namespace. That is the steady budget (1424Mi and 4192Mi), plus one surge pod for each Deployment
during a rollout, plus the operator, migrator, a backup Job and one ad-hoc pod. It covers memory and object counts
only, since the contract budgets no CPU.

## After a stuck first sync

A child that stays `Progressing` holds the root Application in `Running`, and the root will not pick up a new commit
until that operation ends. Fix the child's cause, or run `argocd app terminate-op root`. Inject failure only after
pausing automation on **both** the child and `root`: the root's self-heal reverts a patch to a child's `syncPolicy`.

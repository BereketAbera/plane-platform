# SnakeBrawl production release

Public matches are held pending a reviewed 100-player acceptance run on the VPS. The web serves the branded prelaunch page for lobby and invitation URLs and retains the existing how-to-play, privacy, terms and support pages. `www.snakebrawl.io` redirects to the apex. `ws.snakebrawl.io/health` serves only a static status with `acceptingPlayers: false`. There is no public matchmaking or gameplay upgrade route. The production arena Deployment stays at zero replicas. Scheduled private validation is separate. Public TLS and the existing Traefik pod do not change. A versioned ConfigMap mounts the public markup and status into the existing web image.

The dedicated namespace is restricted, limited to 4250m of CPU requests, six CPUs of limits, 2560Mi requested memory, 4Gi memory limits, ten pods and zero PVCs. After the public arena is quiescent, the 200m/192Mi web pod fits alongside a private Guaranteed 4-CPU/2Gi staging pod. The platform budget remains within node limits. Reopening is a separate reviewed GitOps change. Until then policy rejects an active public arena Deployment.

## Promotion and recovery

1. Verify the two linux/amd64 image archives, manifest digests and vulnerability scan. Import each into the node's k3s containerd k8s.io namespace and confirm containerd recognizes the **full manifest reference** used by Kubernetes. Keep a verified mode-0600 recovery archive beside the active and previous release on the node. The `docker.io/library/snake-production-*` names identify node-local content; `imagePullPolicy: Never` requires the images to be present before sync. Registry access or GHCR publication is unnecessary for this release.
2. Before adding the Application, plan and apply the hosted Terraform foundation through the established SSH tunnel. Review changes by resource address. The first plan created only the SnakeBrawl namespace, quota and defaults. The second updated the CoreDNS rewrite set and the bootstrap AppProject chart. Retain the existing Terraform state.
3. For a future component change, update its pinned digest in `gitops/clusters/plane-prod/platform/snakebrawl/deployments.yaml` and `policy/hosted-images.txt` together. The `promote-app` workflow accepts `snakebrawl` with component `web` or `arena`. Verify the archive is already imported and its package inventory was produced for this exact digest before merging. A digest on its own does not make an image available on another node.
4. Run `scripts/ci/validate-manifests.sh`, `scripts/ci/check-capacity.sh`, Helm/Kubernetes dry-runs and the browser smoke from the game repo. Merge the reviewed change to main once the private workloads are ready, DNS resolves, and the rollback archive and host health watcher are in place. The existing release CI publishes `deploy/plane-prod`; the Argo root reads that branch. The first release adds the namespace to both Traefik provider lists. This replaces its one hostPort pod; monitor Wayline, Frameflow, Grafana and the other existing hosts until the new pod serves them. Later SnakeBrawl-only changes do not roll Traefik.
5. While prelaunch is in force, a recovery must retain zero public arena replicas, the fixed landing page and the blocked gameplay routes. Restore the held web configuration or correct the asset and let normal CI promote it. Keep the provider namespace watch once healthy. Reverting that watch unnecessarily rolls the shared ingress a second time. For a broken Traefik rollout, use the existing Helm rollback and reconcile Git with the running values. Check Argo health, existing public hosts and SnakeBrawl TLS/WSS after recovery. Restore/import the saved OCI archives before a node rebuild or image garbage collection recovery. Secrets stay outside Git. Recreating the namespace would discard the game's telemetry Secrets.

Use the authenticated hosted kubeconfig for `kubectl -n snakebrawl get deployment,pods,events`, `kubectl -n snakebrawl logs deployment/snakebrawl-arena`, `kubectl -n snakebrawl get certificate snakebrawl-tls`, and `kubectl -n argocd get application snakebrawl`. Keep monitoring, metrics and administrative endpoints on the private network.

The hosted scanner re-evaluates the two archived Linux/amd64 package inventories against its current Trivy DB. The verified manifest digest selects the CycloneDX inventory in `policy/node-images/`. The scanner requires the compressed checksum and matching Trivy image config ID and records its inventory provenance. For an upgrade generate a fresh SBOM from the scanned archive, verify its exact OCI manifest/config and platform, and commit the inventory, checksum and pin together. Missing inventories fail the scheduled scan. Keep the full raw archive scan with the game release.

# Known limitations

This page says what the platform is not and what has not been shown. Read it before quoting anything else in these docs.

The platform is a customized deployment of open-source Plane Community Edition v1.4.3 (AGPL-3.0), named Wayline. It is not an original product. It runs in three environments: `dev`, namespace `plane-dev` of a kind cluster on the owner's Mac, started with `make up`; `prod-sim`, namespace `plane-prod-sim` of that same cluster, the promotion target that simulates production; and hosted production, `plane-prod`, on one K3s node on the owner's Contabo VPS, at https://wayline.bereket.dev, with https://grafana.bereket.dev and, from 2026-11-07, https://infisical.bereket.dev. Dev and prod-sim are production-inspired. Hosted production serves its owner, and this repository makes no claim that it is ready for anyone else: [the first table below](#hosted-production-what-to-disclose) says why.

Dev and prod-sim results are as of 2026-11-05 at about 15:15Z, with the wording checked until about 18:00Z, and hosted production's as of 2026-11-07 at about 19:20Z. `docs/evidence/runs/` holds runs published up to 2026-11-07T05:15Z ([index](evidence/runs/MANIFEST.tsv)), and `branding/`, `ci/`, `promotions/` and `security/` hold what was copied there by hand. By [the evidence rules](evidence/README.md#rules) a run with no file there has no result, and most of hosted production's runs have none there yet: [validation.md](validation.md#status-values) says how its rows mark that, and names each raw file. No `VERIFY` or `MEASURE` marker is left on this page. Where nothing measured a figure, Pass 1's text says Not measured in Pass 1.

## Infisical's public route: the risk that stays

The owner chose a public route for Infisical, for its one admin ([ADR 0017](adr/0017-infisical-public-route.md), [docs/infisical.md](infisical.md#the-public-route)). It reached main at about 19:10Z on 2026-11-07 and production with release `f2bff57` at 19:21:48Z. Its tests from outside ran at 19:31Z and are not published: 35 of its 36 rows PASS, the session limit's FAIL as that row stood before `f3ef5c2`, and its Secrets, routes and NetworkPolicies PASS ([H-INF-1 to H-INF-3](validation.md#hosted-infisicals-public-route)). What it leaves, from ADR 0017 and the build's final check:

| Risk | What it means | What would end it |
|---|---|---|
| A flaw in what stays reachable | The sign-in, two-factor, session and secret endpoints, and the web client's code, answer anyone. A bug in them is reachable from the internet, where before it needed the SSH key | Only taking the route away. Policy pins the image, so each upgrade waits until someone has read its new routes again |
| A stolen session works from anywhere | The route accepts a person's session at every call a browser makes, and cannot tell a browser from a script that holds one | Taking the route away, so that a session needs the tunnel again |
| Locks that someone with the password can cause | Wrong codes lock the account, for up to an hour and then until it is unlocked, and need the password first. Wrong passwords move no lock | None planned. The way back in is in [scripts/hosted/README.md](../scripts/hosted/README.md) |
| The guess limit allows about 70 tries a minute, not 10 | The limit gives an address a burst of 10 and one more try every 6 seconds, and Traefik forgets an address after about 1 + 60/n seconds with no request from it, for a limit of n a minute, and starts it again with a full bucket. Measured against the pinned Traefik v3.7.17 in Docker: 10 tries got 200, a try 5 s later got 429, and a burst 9 s later got 10 more 200s. So a client that waits about 8 s between bursts of 10 gets about 70 sign-in tries a minute per address, with as many addresses as it has. The password is 48 random hex characters, two-factor still stands behind it, and Infisical asks for no captcha without `CAPTCHA_SECRET`, which is not set | A limit that keeps an address's count for a whole period, or Infisical's captcha, which needs `CAPTCHA_SECRET` and a way out to its provider |
| Relaxed SSRF protection | `ALLOW_INTERNAL_IP_CONNECTIONS=true` stays, for Kubernetes token review. The server's egress reaches only its database, Redis, the API server and kube-dns, though a name it looks up leaves the node as a query CoreDNS forwards | An Infisical that reviews tokens without it |
| Mail and strangers' text in the log | With no SMTP, any mail Infisical would send, the one-use unlock link among it, goes to its log. It also logs every request's URL with its query string, and the email of each sign-in to an account it does not have, which anyone can send. Loki keeps both for 7 days, behind Grafana's public login | SMTP for the mail, and an Alloy stage that drops those lines or their query strings, at the cost of the request log |
| Traefik holds Infisical's Secrets in memory | Traefik watches namespace `infisical` for the route and the solver, so its providers keep a copy of each Secret there that Helm did not make: `infisical-secrets` with the root keys, `infisical-db`, `infisical-redis` and `restic-password`. Traefik is the pod on the internet | Moving the route, its limits and its Certificate to a namespace that holds only the TLS key, which needs cross-namespace routes in Traefik. The owner's choice |
| Public secret sharing can come back unseen | It is off in the server, and the route refuses it as well. A super admin can turn it on again in the Server Console's environment overrides, which nothing in Git sees | A watch on that setting, beside the claim probe |
| The instance's settings are public | `/api/v1/admin/config` answers anyone, because every sign-in page reads it, so whatever is set there later is readable on the public host. The claim probe watches the two fields that matter | None while the route exists |
| Nothing reads whether two-factor is on | The steps turn it on through the tunnel before the route exists, and the owner reported them done at 18:58Z. On this deploy that order is the only guard. On a new VPS, bootstrap's last line reminds, and `edge.sh open` stops at its note until the operator sets `TWO_FACTOR=on`, which nothing checks | A probe or status line that reads it |
| The route does not wait for its certificate | Once Argo CD applies it, the route answers a request sent through `wayline`'s or `grafana`'s handshake with `Host: infisical.bereket.dev`, before `infisical-tls` exists, because every route shares the same TLS options. Read from the configuration, not run | Two-factor before the route, as the steps do it, or a route that only its own certificate's handshake reaches |

## Namespace separation is not independent clusters

`plane-dev` and `plane-prod-sim` are namespaces in one cluster. **Namespace separation is not equivalent to independent production clusters.** "prod-sim" means production simulation, and the name is deliberate.

| Shared by both environments | Consequence |
|---|---|
| Node, kernel, Docker VM, laptop | Any of them failing takes down both |
| API server and etcd | A control plane failure or corrupted etcd hits both |
| CoreDNS | A bad Corefile hits both. `terraform destroy` removes the `Corefile` key, which breaks both at the next restart |
| Traefik | A bad route or crash hits both |
| Argo CD, root Application | A bad sync or stuck operation can affect both. The root Application's waves order them, so a failure can hold prod-sim back |
| Infisical server | One instance, with a project per environment. Its failure stops both from refreshing secrets, and its `ENCRYPTION_KEY` protects both |
| Monitoring and logging | One Prometheus, Loki, and Alertmanager |
| Memory and disk | One environment can starve the other within quota. ResourceQuota covers memory and object counts, not CPU, and not disk |
| Kernel attack surface | A container escape reaches both |

What separation does exist, measured inside this one cluster. The final `make test` read all of it from about 14:07Z to 14:12Z on 2026-11-05, at `f30a7f5`, with both environments on the final images. The `make test` of 08:40Z to 08:46Z read the same on the second cluster ([summary](evidence/runs/test-20261105T083455Z-37296.txt)):

- Each Plane environment has its own data services, Silo, Infisical project, machine identity, AppProject, and quota. Their Postgres system identifiers, Valkey run ids, buckets and volumes all differ, among 97 checks ([SEP-2](evidence/runs/separation-state-20261105T140019Z-56547.txt)).
- NetworkPolicy has no rule from one Plane namespace to the other, and real attempts confirm it: 120 rows each way all time out, with the real clients and their own credentials timing out too, among 384 checks ([SEP-1](evidence/runs/separation-network-20261105T140019Z-56547.txt)). On 2 of the 6 ports a pod at home times out as well, so those rows do not show the target was up.
- `api` may reach Traefik for its self-dial, and Traefik routes by Host, so a compromised `api` can request the other environment's public hostname, and gets what a browser would ([what real runs found](#what-real-runs-found)). The GAP rows last read that in the final run ([routes](evidence/runs/routes-20261105T140019Z-56547.txt)). `gitops/platform/network-policies/plane-dev.yaml` records this gap.
- Cross-project access fails with 403 in both directions, on list, single read and slug lookup, from the host and from a pod in each namespace, 28 rows of 28 ([isolation](evidence/runs/infisical-isolation-20261105T140019Z-56547.txt)).

Promoting from dev to prod-sim exercises process and tooling. It does not exercise an independent environment. Hosted production is one, a cluster of its own on another machine, and it still shares this repository, GHCR, the release job, the owner's GitHub account, and the Mac that holds its evidence key, its kubeconfig, its secret zero and the only copy of its backups off the VPS.

## What Terraform does and does not do

On kind, Terraform provisions no infrastructure. On hosted production it reads the VPS without owning it, owns its three DNS records, and bootstraps the cluster.

| Created by | Resources |
|---|---|
| **kind CLI**, through `scripts/cluster-up.sh` | Cluster, node, CNI, port and volume mounts |
| **Docker Compose**, through `infrastructure/local-services/` | Registry, pull-through caches, Git daemon |
| **Terraform**, `environments/local` | Namespaces and labels, ResourceQuota, LimitRange, CoreDNS rewrite, Argo CD release, AppProjects, root Application |
| **Terraform**, `infisical/terraform` | Infisical projects, environments, identities, memberships, Kubernetes Auth config |
| **Argo CD** | Everything else in the cluster |
| **Scripts** | Secret zero, Infisical bootstrap and seed |
| **`scripts/hosted/provision-node.sh`**, over SSH | The hosted node: an admin user and key-only SSH, packages, resolvers, sysctls, automatic security updates, the firewall, and K3s at its pinned version |
| **Terraform**, `environments/prod-host` | The VPS, read with `data "contabo_instance"` only, because a resource could reinstall or cancel it. Three Vercel records, `wayline`, `grafana` and `infisical`, each an A record for 5.253.234.127, with `prevent_destroy` |
| **Terraform**, `environments/prod` | Hosted namespaces with their PSA levels, ResourceQuota and LimitRange from `infrastructure/hosted/plane-prod/capacity.yaml`, storage class `local-path-retain`, K3s's `coredns-custom` rewrite, the Argo CD release, AppProjects and the root Application |

| **Scripts**, `scripts/hosted/` | The deploy key, secret zero, the restic password, Infisical's bootstrap and seed, alert delivery and the recovery bundle |

`environments/dev` contains no Terraform, and is an interface document. `environments/prod` became hosted production's cluster root, on Contabo, and the Hetzner plan in [future-hetzner.md](future-hetzner.md) did not happen. Other limits:

- State is local, under `.local/terraform/`, with a local file lock only. Each Infisical backup copies the Infisical root's state, on the same machine.
- Argo CD does not manage itself, so upgrading it is not GitOps.
- `terraform destroy` removes the CoreDNS `Corefile` key. Delete the cluster afterwards instead of reusing it.
- The Infisical root's state shares a lifecycle with the instance. `make destroy` keeps it for a clean restore, and `scripts/infisical-bootstrap.sh` moves it aside on a truly fresh instance. That path has no recorded run.
- Hosted production's state is local too, under `.local/hosted/plane-prod/terraform/` on the Mac, with a local file lock, and a copy in the recovery bundle. Each apply leaves the bundle stale until `make remote-bundle TARGET=plane-prod` runs again.
- Do not run `terraform destroy` in `environments/prod`. It deletes the namespaces, and with them every claim, and the Retain volumes stay with nothing bound to them.

The window was unresolved in research, and the fallback has not been exercised. The cold install pulled everything through empty caches once and got there, leaving 1.992 GB in the Docker cache ([readings](evidence/runs/clean-install-20261105T105546Z/disk-after-install.txt)). `metrics-server` read Progressing and then Degraded up to 968s of the wait for Infisical ([log](evidence/runs/clean-install-20261105T105546Z/make-up.txt), lines 752 to 767), and no file says what held it, so this does not show that no limit was met |
| Network assumption | `scripts/cluster-up.sh` fails if the `kind` network is outside `172.16.0.0/12`. The allow list on the internal routes uses the same range, so a node network outside it makes those UIs answer 403 |
| Browser | Chromium only. On dev a real browser signed in, finished onboarding, and opened a board, the page editor, admin and the `/spaces/` page, on the images from `1563cbf` ([AUTH-5](evidence/branding/live-dev/README.md)). On the final images it held two tabs in sync through a `live` restart ([RT-2b, RT-3](evidence/runs/RT-2b-RT-3-20261105T073208Z.txt)), and after the restore it signed in on prod-sim and held a session on each host at once ([record](evidence/branding/live-final/README.md)). A dev session gets 401 on prod-sim's host ([AUTH-4](evidence/runs/AUTH-4-20261105T062750Z.txt)). Safari and Firefox were not tested in Pass 1 |
| The Mac's sleep pauses the platform | The kind node runs in Docker Desktop's VM, so a closed lid pauses everything. On 2026-11-05 the lid closed at 15:49Z and opened at 20:19Z, and the Mac woke for about 45 to 90 s every 16 minutes between. Prometheus has holes for those hours. On those wakes the node's load reached 72 and its CPU pressure 84%, probes failed, 5 Applications read `Unknown` for a time, and 8 system containers restarted, among them the scheduler, the controller manager and Argo CD's repo server. No Plane workload or data service restarted, and `make test` then passed whole ([record](evidence/runs/host-sleep-20261105T202039Z.txt), [make test](evidence/runs/MAKE-TEST-20261105T202039Z.txt)). One sleep, and not a study of it |
| Do not prune | `docker system prune -a` on this machine would remove cached images for unrelated containers that cannot be re-pulled anonymously |

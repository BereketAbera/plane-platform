# Validation

The test matrix for Wayline, a customized deployment of open-source Plane Community Edition v1.4.3 (AGPL-3.0) on a local
kind cluster. Wayline is not an original product, and most of what these tests exercise is upstream Plane behaviour
running under this platform's configuration.

## Read this first

This page records what ran up to 2026-11-05T00:53Z, the newest entry in [`runs/MANIFEST.tsv`](evidence/runs/MANIFEST.tsv).
Work is still landing, so a later commit may not be covered here. Newer runs wait in `.local/evidence-raw/` until
`make publish-evidence` copies them. A row names such a run where it matters and keeps its status, because
[a run with no file here has no result](evidence/README.md#rules).

**What has a result.** Plane runs on this platform. All 14 Argo CD Applications read Synced and Healthy
([2026-11-04T23:29Z](evidence/runs/plane-prod-sim-status-1.txt), and again at
[2026-11-05T00:05Z](evidence/runs/drill-clean-restore-20261105T000555Z.log)). `make test-e2e` passes in plane-dev on the
branded images, 38 steps ([2026-11-05T00:12Z](evidence/runs/branded-dev-smoke-1.txt)), and in plane-prod-sim on upstream
images, 37 steps ([2026-11-04T23:59Z](evidence/runs/plane-prod-sim-smoke-2.txt)). The NetworkPolicy matrix passes from both
Plane namespaces. Real attempts to cross between the environments all failed, as they should. A real browser has signed in
on dev once.

**What failed.** Three rows read FAIL. AUTH-6: a returning browser keeps the old page after a promotion. CI-7: the last
complete image scan failed its policy. BR-3: `/source` answers 404 logged out while the repository is private. Two rows read
BLOCKED: NET-2c and CI-6b.

**What has no result.** A clean install, teardown and recreation, a full restoration, secret rotation, the failed-deploy
drill, the load test and `make test-alert` have not run. Those rows say NOT RUN. The platform came up stage by stage on one
cluster, with some steps by hand, so nothing here shows that one `make up` works from nothing.

**What ran on what.** plane-prod-sim has not run the branded images yet. Many dev results also come from before the branded
images were promoted. Each row says which.

A full column of PASS would not change these limits:

- **It would not show production readiness.** This runs on one laptop, on one kind node, in one Docker VM, with no TLS
  and one replica of most workloads. It is local and production-inspired. This matrix makes no production readiness claim.
- **Namespace separation is not equivalent to independent production clusters.** `plane-dev` and `plane-prod-sim` share
  a node, a kernel, a control plane, an API server, an ingress controller, an Argo CD and an Infisical. The NET and SEP rows
  test NetworkPolicy and credentials inside that one cluster. They do not test isolation between clusters.
- **`prod-sim` is a simulation.** It has no real users, no real data and no independent failure domain.

## Status values

| Status | Meaning |
|---|---|
| PASS | The test ran, met its criterion, and its raw output is in [`docs/evidence/`](evidence/README.md) |
| FAIL | The test ran and the system misbehaved |
| BLOCKED | The test could not run or finish because something it depends on failed or is missing. This says nothing about the system under test |
| NOT RUN | The test was not attempted, or it was attempted and no evidence was captured |

A row changes status only when its evidence is committed. Some rows check more than one thing. Such a row is PASS only
when all of them pass, so a row with one part proven and another not is split in two, or stays NOT RUN and says what did
run.

How script outcomes map to status:

| Script | Outcome | Status |
|---|---|---|
| `tests/e2e/smoke.py` | Exit 0, all named steps PASS. A step reading SKIP does not apply as things stand, and proves nothing either way | PASS |
| `tests/e2e/smoke.py` | Exit 1, at least one FAIL | FAIL |
| `tests/e2e/smoke.py` | Exit 2, no FAIL but a step BLOCKED | BLOCKED |
| `tests/separation/*.py`, `tests/routes/internal-routes.sh` | The same exit codes. A GAP row in the routes test states what it does not close, and is not a failure | The same |
| `scripts/test-netpol.sh` | Any row FAIL | FAIL |
| `scripts/test-netpol.sh` | No FAIL, any row INCONCLUSIVE, which is a DNS failure, no result, or a target that did not answer | BLOCKED, never PASS. Since `01ab74c` this exits 2, and a row that needs something outside the cluster is counted apart and does not make an offline run non-zero |
| `scripts/restore.sh` | A proof step recorded as NOT RUN | Not PASS, even if every other step passed |
| `tests/drills/*.sh` | The last line, `RESULT PASS` or `RESULT FAIL` | The same |
| `tests/load/run.sh` | A k6 threshold fails, but the run finished and captured its data | PASS for the measurement. Report the threshold failure in the row, because the thresholds are starting points (`tests/load/plane.js`) |
